# 認可ルール（正本）

AI エージェントと人間が共有する、認可ルールの正本。

- 認可に関わる実装・レビューの前に必ず読む。
- 変更は人間の確認を取ってから行う。AI が単独で書き換えない。
- テストの期待値はこの表に従う。テストを先に書き換えて通さない。

## 共通方針

- 拒否時の応答：未ログイン → ログイン画面へ（API は 401）／他人のデータ → 404 または 0 件（存在を隠す）
- 管理者：`profiles.role = 'admin'`（`public.is_admin()`）。リソースごとに下の表で定める
- 画面以外の入口：API ルート（`web/app/api/**`、service_role 使用）と、ブラウザから Supabase への直接アクセス（anon key + RLS）
- DB の直接アクセス：Supabase。対象テーブルは RLS 有効。service_role はサーバーのみ

## リソース：face_landmark_snapshots（顔の構造指標）

顔ランドマークから算出した構造指標（顎幅・頬幅・顎幅/頬幅・縦横比・顔の向き）。生体情報に近いため、同意した本人だけが扱える。

- 所有の単位：個人（`face_landmark_snapshots.user_id`）
- 保存する内容：構造指標と姿勢・品質のみ。478 点の座標や画像は保存しない
- 関連データ：
  - `look_record_id` は本人の `look_records` だけを参照できる。写真記録が消えたら紐づく snapshot も消える（cascade）
  - 同意は `face_landmark_consents`（行がある = 同意済み）。権限は snapshot と同じで、管理者も他人の同意状況は見られない
- 入口：ブラウザから Supabase へ直接（RLS が唯一の判定）。service_role は使わない

| 操作 | 未ログイン | ログイン中の他人 | 所有者 | 管理者 |
|---|---|---|---|---|
| 一覧を見る | 拒否 | 0 件 | 許可 | 0 件（本人以外と同じ） |
| 詳細を見る | 拒否 | 0 件 | 許可 | 0 件 |
| 登録する | 拒否 | 拒否（他人名義・他人の記録の参照も拒否） | 同意済みなら許可 | 自分の分のみ（所有者と同じ） |
| 更新する | 拒否 | 拒否 | 拒否（保存後は変更不可） | 拒否 |
| 1件削除する | 拒否 | 0 件 | 許可 | 0 件 |
| 全件削除する | 拒否 | 0 件 | 許可 | 0 件 |
| 同意する／取り消す | 拒否 | 本人の分のみ（他人の同意は変えられない） | 許可 | 本人の分のみ |

「拒否」は DB の権限エラー（42501）。「0 件」は RLS で対象が見えずエラーにならない。

状態による制限：

- 同意していない（`face_landmark_consents` に行が無い）→ 所有者でも登録不可
- 同意を取り消す → その場で本人の snapshot を全件削除し、以後の登録を止める（取り消しと登録が同時に走っても snapshot は残らない）
- 退会（auth.users / profiles 削除）→ cascade で全件削除

## リソース：profiles（プロフィール）

今回は `role` と `stripe_customer_id` の変更権限だけを定めた。それ以外の行は既存の動作を書き写したもの。

- 所有の単位：個人（`profiles.id = auth.users.id`）
- 入口：ブラウザから Supabase へ直接、API ルート（service_role）

| 操作 | 未ログイン | ログイン中の他人 | 本人 | 管理者 |
|---|---|---|---|---|
| 見る | 0 件 | 0 件 | 許可 | 許可（既存の `profiles_select`） |
| 表示名などを更新する | 0 件 | 0 件 | 許可 | 本人の分のみ |
| `role` を変更する | 拒否 | 拒否 | 拒否 | 拒否（service_role と管理用 SQL のみ） |
| `stripe_customer_id` を変更する | 拒否 | 拒否 | 拒否 | 拒否（Stripe 連携の API ルートが service_role で設定） |
